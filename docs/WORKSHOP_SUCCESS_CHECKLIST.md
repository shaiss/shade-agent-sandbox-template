## 🎪 Workshop Day Checklist

### 30 Minutes Before:
- [ ] Check all account balances
- [ ] Verify internet connection
- [ ] Open all necessary tabs
- [ ] Test microphone/screen share
- [ ] Deep breath - you've got this!

### During Introduction (0-5 min):
- [ ] Start with bridge horror stories
- [ ] Show $2.8B hack statistics
- [ ] Ask audience about their pain points
- [ ] Build anticipation for the solution

### During Demo (5-10 min):
- [ ] Show pre-demo setup clearly
- [ ] Count down during transaction
- [ ] Show both chain confirmations
- [ ] Compare to traditional bridge time/cost
- [ ] Celebrate the success!

### During Code Review (10-20 min):
- [ ] Explain derivation simply
- [ ] Show no private keys stored
- [ ] Highlight the one-line signature request
- [ ] Let them see how easy it is

### During Q&A (20-25 min):
- [ ] Use visual aids for complex answers
- [ ] Refer to documentation
- [ ] Admit beta limitations honestly
- [ ] Get them excited about building

### Closing (25-30 min):
- [ ] Share resources and links
- [ ] Mention hackathon/grants
- [ ] Give them the GitHub repo
- [ ] End with "What will you build?"

## 🚨 If Things Go Wrong

### Demo Fails:
1. Stay calm, say "Perfect teaching moment!"
2. Show the error, explain what happened
3. Switch to backup (video/deployed version)
4. Emphasize: "Beta software pushing boundaries"

### Audience Seems Lost:
1. Pause and check understanding
2. Use more analogies (universal remote)
3. Show visual diagram again
4. Do a mini-recap

### Technical Questions You Can't Answer:
1. "Great question! Let me connect you with our dev team"
2. Point to documentation
3. Suggest they try it and experiment
4. Never make up answers
